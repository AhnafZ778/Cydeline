# Authorized live SOC roadmap

Ahnaf authorized implementation of the seven-milestone plan in this conversation. Defaults: unified SOC console, local-first, learners and instructors, optional desktop/SIEM, reviewed multi-route adversary. Keep Ember styling and actual evidence as the source for presentation. Existing fixture exercises remain separately labeled. Milestones below are implementation scope, not completed claims.

1. One complete live shift: actual target, trusted orchestration, local red agent, SSE, persistent case, response, verification, debrief.
2. Investigable company: linked entities, evidence notebook, queries, timeline, genuine benign workflows and business disruption.
3. Branched campaign: browser session and reporting credential, state-aware model context choice, credential revocation, pressure and measurable recovery.
4. Analyst tools: on-demand desktop, optional Elastic, artifacts/export, forensic follow-up and checkpoint practice branches.
5. Learning progression: coached/independent/assessment, identity/phishing/endpoint families and evidence-linked skills.
6. Instructor and team workflows: profiles, cohorts, assignments, reviewed scenario publication, injects, ownership and handoffs.
7. Advanced training: evidence-limited defensive assistant, separate AI judgment assessment, disposable Linux VM provider and private range host.

## Acceptance
Every milestone must have an observable user journey. No fabricated target results, client-side scoring of live attempts, hidden assessment attribution, fabricated tool success, or unrecorded AI fallback. Preserve existing canonical v1 enums; add versioned capability extensions for later campaigns. Store immutable scenario/rubric versions with every attempt. Model inference cannot block defense or execute stale decisions. Display pause is distinct from practice pause; assessment cannot pause. Failed runs have debriefs. Broad actions must show measured legitimate disruption. Replay is read-only; practice branches are new runs.

## Implementation sequence and verification
Begin with Saad S2 actual target, then S3 control/orchestration and S4 scorer, integrating Tanvir B3 and Ahnaf A3/A4. Continue milestones in order with project-native integration/browser checks and harness checkpoints. Current blockers and incomplete external-tool execution must be recorded explicitly. No deployment, research efficacy, or completed benchmark is implied by this plan.
